# Log — 2026-08-12

Session covering the inverted sweep, the chain-form primitives, the sheaf-side
computations, and a codebase audit. Commits `a1af924` through `c8deb83` on
`tui-query`.

## Math

1. **Kummer decomposition applies to the graded layer, not the composed one.**
   Each layer is `y -> y^n + c`, a translated Kummer cover, abelian. The
   composed chain's Galois closure sits in an iterated wreath product,
   non-abelian, so it does not decompose into rank-1 pieces. Gemini's Step 2 is
   correct per layer and wrong for the composite. Not implemented: `Graded`
   returns partial composites, and there is no accessor for the layer morphism.

2. **Ramification is computable by factorisation.** `LocalAt` factors
   `P(y) - c` over `F_{p^d}` and reads `(e_i, f_i)` off it, with
   `sum e_i f_i = deg P`. Ramified means some `e > 1`; wild means `p` divides
   such an `e`.

3. **Inseparable is not ramified.** `x^2 + a` in characteristic 2 and
   `x^3 + a` in characteristic 3 factor as perfect powers at every point.
   Inferring ramification from multiplicity alone reports the whole line as
   branch locus. `Local` now carries a separability flag taken from the
   derivative. Wild ramification needs `p | e` *with* the map separable, which
   `x^4 + x` over `F_3` at `c = 0` gives as `x(x+1)^3`.

4. **Fiber counts are not ramification data.** `FiberCounts` counts rational
   points and so conflates `e` with `f`. A fiber smaller than the degree is not
   evidence of branching.

5. **The faithful and canonical lifts differ by a constant factor, not a growth
   class.** Measured over four windows: max flat paths against max distinct
   faithful states gives 3.64, 4.27, 4.12, 4.36 across a 20x range. Runs are
   short, so reordering collapses almost nothing, and states keyed by
   `(source, multiset)` never merge across sources. An earlier argument that
   binary partitions bound this was wrong.

6. **Words and paths differ by orders of magnitude.** At `p = 987391`: 6361
   words against 50450299988 paths. `kCap = 400000` sits between them, so the
   spectrum walk is not a truncated spectrum but a sample of a different object.

7. **`deg P_red` is computed by running the Artin-Schreier fold**, not by the
   two-block closed form, which was a fit over a scanned range and is not
   proved. Depth one folds to the odd part of the degree for every exponent 2
   through 25. A two-block word with an odd inner constant blocks at 4 against
   an odd part of 3; the same word with an even one folds through to 3.
   Evaluating the base before folding collapses both to the odd part.

8. **The Weil bound checks the fold from outside itself.** For a two-block word
   over `F_{2^d}` at `d = 4, 6, 8`, `|sum_x psi(P(x))| <= (deg P_red - 1) sqrt(q)`
   with `deg P_red` from `SwanAtInfinity`. Before this nothing in the tree could
   contradict `H1Dimension`.

9. **The base is a parameter.** `point_count` hardcoded characteristic 2; that
   was an implementation choice reported as a property of the problem. Element
   codes are now base-`r` digit vectors. Every other 2 in the new code is the
   arithmetic base from `p = 2^m + q^n` and belongs there; `as_fold` is
   characteristic two by construction.

10. **ell-adic content appears only at odd base.** At `r = 2` every additive
    character is trivial or the sign and every trace is an integer, so `Q_ell`
    is scaffolding for the theorems rather than an input to any computation.
    Gauss and Jacobi sums are the first objects here that are neither counts nor
    dimensions, and they degenerate at `r = 2`.

11. **Exponent spectra, both attained in-window.** Enumerating `n >= 2` edges to
    the 54e9-th prime: Set B realises every `n` in `[2, 17] = [2, log_5 p_max]`,
    Set A every `n` in `[2, 25] = [2, log_3 p_max]`. Set B is 97.9% `n = 2`;
    Set A is nearly flat. So Set A carries the top of the degree spectrum. A
    window is a sample: the inequality is an identity, the attainment is not.

12. **The graded layer is small and nearly a partial function.** 159065 edges
    with `n >= 2` against 54e9 primes, enumerable in 0.23 s with no table.
    Exactly one prime below 1.456e12 carries two Set B higher edges,
    `2213 = 2^2 + 47^2 = 2^4 + 13^3`, plus seven with one of each kind. Direct
    composition is 0.68% of edges, so composite degrees route through `n = 1`
    edges.

## Code

13. **`Field` is duplicated three ways with three different bounds** —
    `1<<24`, `1<<16`, `1<<14` in `point_count`, `characters`, `ramification`.
    `FiberCounts` accepts fields `LocalAt` rejects, silently. Correctness, not
    style.

14. **`Word` and `Folded` are named backwards** against `notation.md` §2.4.
    `Word` is a path; `Folded` is the word.

15. **Nothing in `src/graph/` reads a table.** `ComputedMask` recomputes what
    `hit_mask` stores. The `MaskFn` callback exists precisely so a table-backed
    mask can be supplied and is unused.

16. **No threading in any of it**, while `Session` already shards:
    `scan_threads` sets `shards`, `RunShard(i)` is a worker per shard with a
    bounded queue. `BranchLocus` is `q` sequential factorisations and `Sum` is
    independent per word.

17. **The plan IR already exists.** `ScanPlanRequest` / `ScanPlan` with
    projection, filters, residuals and split-level tasks; `PlanStore` with
    submit/fetch/cancel, task batching, TTL and its own thread; REST routes and
    `Session` dispatch on the advertised mode. Open: whether a chain computation
    is a second plan type or a stage over `ScanStream`.

18. **`pp-graph` uses the planner only for file discovery.** `PlanPaths` sets
    `scan_threads`, calls `PlanFiles` for paths, hands them to DuckDB, and
    discards the streaming and the sharding.

19. **The Lua module pushes flat tables.** `lua_newtable` + `lua_setfield`
    throughout, no userdata, no metatables. Manipulable objects need a different
    mechanism.

20. **`pp-graph --mode chain` is the only surface** any of the seven new modules
    has. Reports root, degree, skeleton, `deg P_red` and `dim H^1_c` per word,
    with `--base --deg --theta` giving the coproduct trace and its first two
    moments.

21. **Sweep window from `min`/`max` of an arbitrary array was a 650x
    regression.** `pp_process_prime_array` spanned `2^50` to `2^61`, enumerating
    `q` to 1.5e9 per exponent. The suite went 1.5 s to 980 s and I attributed it
    to test-binary contention. Sweeping `[p, p]` per prime fixes it.

22. **Test naming.** Names were sentences, some over forty characters. Renamed
    across the suites written this session; then a new suite was written in the
    same style and renamed again.

## The distribution of `n`, read from the table

Warehouse at 60,032,000,000 primes, `p_max = 1,625,471,567,381`. 167,217 rows
with `n >= 2` over 167,209 distinct `p` — eight primes carry two, confirming
against the table what the sweep found. 80,368 distinct bases, 161 with `q = 3`.

23. **Counts by exponent.** `n = 2` is 163609 (97.84%), then 2760, 419, 145, 63,
    43, 28, 20, 18, 15, 12, 13, 15, 9, 7, 9, 6, 3, 3, 6, 4, 3, 4, 3. Support is
    exactly `[2, 25] = [2, floor(log_3 p_max)]` with no gaps; from `n = 18` up it
    is entirely `q = 3`, since `X^{1/25}` is about 3.1.

24. **The 97.8% is not a distributional constant.** By window it runs 75.02,
    83.94, 89.94, 93.90, 96.24, 97.84 percent at `1e7, 1e8, 1e9, 1e10, 1e11` and
    the full range. Monotone, no plateau, heading to 100. Its resemblance to a
    two-sigma tail is coincidence.

25. **`log count(n) - log n` is linear in `1/n` with slope `ln X`.** Regression
    over `n = 2..9` gives slope 26.824 against `ln X = 28.117`, ratio 0.954, with
    `R^2 = 0.99971`; over `n = 2..12`, slope 26.954, `R^2 = 0.99964`. So the
    distribution is exponential in `1/n` at a rate set by the window, which is
    why no fixed share falls out and why the skew is the reparameterisation
    rather than the process.

26. **Normalising by available bases is bounded.** `count(n) / pi(X^{1/n})` runs
    1.80, 2.20, 2.61, 2.95, 2.72, 3.11, 2.93, 2.75, 3.04, 2.98, 2.70 — rising to
    about 3 by `n = 5` then flat within noise. Two model corrections were tried:
    the `m`-range is not the issue, since the exact candidate count matches the
    estimate to under 3%; using density `1/ln p` per candidate rather than
    `1/ln X` collapses the tail from 2.5-3.5 down to 0.9-1.4, because for large
    `n` the term `q^n` is small and `p` is near `2^m` rather than near `X`.

27. **Chebyshev weights are the ones that make it clean.** `Lambda(q^n) = log q
    = log(q^n)/n`, so `psi(x) = integral of log t d J(t)` and the `1/n` of
    Riemann's `J` is already inside the von Mangoldt weight. Applying it here,
    stratum `n` contributes `count(n) * (ln X)/n ~ c * X^{1/n}`: both the `n` and
    the `ln X` cancel, leaving the strata as clean powers with the same residual
    `c` near 3.

28. **The residual is a singular series, and its source is identifiable.**
    `Lambda(2^m) = log 2` for every `m`, so the Chebyshev-weighted `k(p)` is
    `log 2 * sum_m Lambda(p - 2^m)`, an additive convolution `Lambda * Lambda`
    with one argument restricted to powers of two. That is Goldbach-shaped
    machinery on a thin set, and a singular series is exactly what it produces.
    The local factors are genuinely `n`-dependent: `l | 2^m + q^n` needs
    `-q^n` in the subgroup generated by 2 mod `l`, which turns on the image of
    the `n`-th power map — for `l = 3` and `l = 5` the subgroup is everything and
    the factor is `n`-free, for `l = 7` it is the residues, so even `n` loses
    nothing and odd `n` loses a third of its `m`. Not computed.

29. **`n = 1` puts this in de Polignac territory.** Odd numbers never of the form
    `2^m + prime`, killed by covering congruences. The flat layer is the hard
    case and the graded layer is the tractable one.

30. **Untested lead: generalised von Mangoldt for chains.** A depth-`j` chain is
    `j` successive prime-power summands, so its natural weight would be a `j`-fold
    convolution with powers of two in alternating slots, `Lambda_k = mu * log^k`
    in flavour. Whether the convolution structure survives `q -> q^n` between
    levels is unchecked and probably does not, since the convolution is additive
    while the chain composes in the exponent.

## de Polignac primes

31. **The count is a row count, not a scan.** No `flat_parts` row is written when
    the mask would be zero, so primes with no `n = 1` representation are
    `count(primes) - count(flat_parts)`. That is metadata only and returns in
    half a second: 60032000000 - 49262159553 = 10769840447, or 17.94 percent.

32. **It decomposes as expected.** Full scan of the `primes` table, 37 s:
    `sum(k) = 113233716794` so the mean is 1.8862; `k = 0` is 10769829558; and
    the difference from the mask-zero count is **10889** — primes whose every
    representation uses `n >= 2`, in sixty billion. Against the 167209 primes
    carrying a graded edge, 156320 carry both kinds.

33. **The set is de Polignac primes, not de Polignac numbers.** The classical set
    is odd integers never of the form `2^m + prime`; ours is that condition
    restricted to primes. The density of the former has bounds only, from
    Romanov below and Erdos's covering congruences above.

34. **Mean `k` is asymptotically constant, and that is why this is a density
    question.** `log_2 p` gives more exponents to try while `1/ln p` makes each
    less likely, and the product is flat: by decade from 1e4 to 1.6e12 the mean
    runs 1.8865, 1.8702, 1.8798, 1.8809, 1.8777, 1.8828, 1.8851, 1.8834, 1.8906.
    Nine decades inside half a percent. The heuristic value is `2/ln 2 = 2.885`
    times a local correction, so the correction is about 0.65.

35. **The zero rate is nonetheless still climbing.** By the same decades: 13.15,
    14.96, 15.53, 16.27, 16.95, 17.31, 17.61, 17.96, 17.98 percent. Increments
    over the last four full decades are 0.37, 0.30, 0.35 — decelerating but not
    converged. The final row covers only `1e12` to `1.63e12`, about seven percent
    of its decade, so its flatness is proximity to the previous row rather than a
    limit. **17.94 percent is a running value and must not be quoted as a
    density.**

36. **Fixed mean with a rising zero rate is heterogeneity, not drift.** Poisson at
    `lambda = 1.883` predicts a flat 15.21 percent; the measured rate crosses that
    around 1e5 and reaches it plus eighteen percent by 1e11. The `m`-trials are
    not identically distributed — at small `m` the difference is near `p` and the
    density is `1/ln p`, at large `m` it is small and the density much higher —
    and that spread widens with `p` while the mean stays pinned. For independent
    trials with fixed mean, spreading the probabilities raises the product
    `prod (1 - p_i)`. Prediction, untested: the variance of `k` grows across
    decades while the mean holds.

37. **Cost note.** Grouping by `floor(log10(p))` cost 2 m 38 s against 37 s for
    the plain aggregate. The decade key was the expense; an integer bucket or a
    bit length would have been most of the difference.

## Prior art worth reading

Sage's `sage.rings.function_field` — places, valuations, ramification indices,
differents as first-class objects over `F_q`; the closest existing model for
what `LocalAt` gropes at with a struct of ints. Magma's function-field package
for API shape. PARI/GP as the precedent for a small functional language driving
a C library. Macaulay2 for a language whose types are the mathematical objects.
Halide for separating the algorithm from the schedule, which is the argument for
Lua expressing the computation and C++ deciding the threading. Torch7 for the
Lua-over-C-kernels architecture at scale.
