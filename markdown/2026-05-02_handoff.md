## Current Blockers

1. Rust `primeparts-commit` is not production-ready.

   The binary builds and validates manifests, but its SqlCatalog layer does
   not yet interoperate with the current PyIceberg-created SQLite schema. It
   fails with `no such column: iceberg_type` before append/HMS sync.

2. Rust HMS sync is not currently a sync-only tool.

   The Rust HMS code is reached only after a successful Rust append. Use
   `pixi run sync-hms` for the live warehouse.

3. No interactive TUI frontend exists yet.

   The low-level native read/status ABI is now working against the production
   `truncate[10000000000](p)` warehouse, but there is still no first-screen
   TUI application wrapped around it.

## Recently Resolved

1. `warehouse_standing()` now accepts the compacted layout.

   The checker no longer assumes `commit_seq=...` partition directories. It
   accepts `p_trunc=...` production files, still flags legacy `commit_seq`
   directory collisions, and tolerates compacted files whose manifest metrics
   omit `commit_seq` bounds while snapshot summaries still carry
   `funbuns.max_commit_seq`.

2. Native TUI/status reads now work with `truncate[10000000000](p)`.

   `native/include/primeparts/ui_iceberg.h` and `native/src/ui_iceberg.cc`
   still serve as the intended C/C++ read/status boundary, but they now bypass
   iceberg-cpp's partition-spec parse failure by reading metadata JSON
   directly and using iceberg-cpp only for manifest-list Avro reads.
