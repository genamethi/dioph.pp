## Current Blockers

1. Rust commit/check coverage is still partial.

   Generation commits now default to Rust `primeparts-commit`, and HMS sync
   dry-run/live paths are Rust-backed in the TUI. The warehouse-standing check
   action (`c`) still shells through the Python checker.

2. Native generation writer path needs stabilization.

   `primeparts-generate` currently crashes inside the Parquet writer path
   during file emission, which blocks fully native generation+commit TUI flows.

3. TUI hardening and deeper workflow screens are still pending.

   `native/src/tui_frontend.c` now runs core operations from the ops view and
   reports command exit status/output snippets in-pane. The current gap is
   mostly robustness and UX depth around the modal, richer error handling,
   nonblocking long-running ops UX beyond the current background launch, and
   full browse/query execution panes.

## Recently Resolved

1. `warehouse_standing()` now accepts the compacted layout.

   The checker no longer assumes `commit_seq=...` partition directories. It
   accepts `p_trunc=...` production files, still flags legacy `commit_seq`
   directory collisions, and tolerates compacted files whose manifest metrics
   omit `commit_seq` bounds while snapshot summaries still carry
   `funbuns.max_commit_seq`.

2. Native TUI/status reads now work with `truncate[10000000000](p)`.

   `native/include/primeparts/ui_iceberg.h` and `native/src/ui_iceberg.cc`
   still serve as the intended C/C++ read/status boundary, but they now bypass
   iceberg-cpp's partition-spec parse failure by reading metadata JSON
   directly and using iceberg-cpp only for manifest-list Avro reads.

3. Rust SqlCatalog schema-evolution hook for older SQLite catalogs.

   Rust `primeparts-commit` now checks `iceberg_tables` and adds/backfills
   `iceberg_type` when missing. This addresses the prior
   `no such column: iceberg_type` failure mode.

4. Rust metadata parse blocker remains on production truncate width.

   Live production commit attempts still fail before append when Rust loads
   table metadata that includes `truncate[10000000000](p)`. In the vendored
   iceberg-rust stack, this currently fails during metadata parse
   (`DataInvalid` / `TableMetadataEnum`) before transaction apply.

   The `iceberg_type` schema-evolution hook above is still useful and resolves
   one catalog-schema mismatch, but it does not remove the current
   truncate-width metadata parse blocker.
